Community Collaboration Platform Guide

The Love and Deepspace theorycrafting community runs on collaboration across many platforms. This guide maps where the work happens, how to join existing projects, and how you can contribute regardless of your skill level.

Overview

Community collaboration accelerates everyone's progression — one person's discovery becomes everyone's advantage. The Love and Deepspace community has built an impressive ecosystem of calculators, data collection projects, tier lists, and theorycrafting resources through voluntary cooperation. No single player can collect enough data to produce statistically significant results. But when a hundred players contribute their domain drops, their build tests, and their observations, the community gets answers that benefit every player. This guide is your entry point to that ecosystem.

The theorycrafting community operates across multiple platforms, each serving a distinct purpose. Discord servers host real-time discussion and bot-assisted calculations. Reddit handles broader discussions, tier list voting, and Q&A. Google Sheets serve as shared data collection and planning tools. GitHub hosts open-source calculator code, datamine parsers, and automated tools. Understanding which platform to use for which task is the first step to becoming an effective contributor.

You do not need to be a programmer, a mathematician, or a whale to contribute. The community values data collectors, testers, proofreaders, and community supporters as much as it values coders and analysts. If you can run a domain and write down your drops, you can contribute. If you can compare two builds and report which felt stronger, you can contribute. There is a role for everyone.

How to Join Existing Projects

The community has dozens of active projects running at any time. Drop rate tracking, tier list maintenance, DPS calculator updates, and event reward optimization are all ongoing efforts that need fresh contributors. The path from observer to contributor follows a natural progression.

1
Find a project that matches your interest
Identify what kind of project excites you: DPS calculator work if you enjoy numbers, drop rate tracking if you want to help the community farm efficiently, tier list maintenance if you have strong opinions about character strength, or tool development if you code. Browse Discord server project boards and Reddit pinned threads to see what is active.
2
Read the project's contribution guidelines
Most projects have a README, a pinned post, or a dedicated channel explaining how they accept contributions. Read this carefully before submitting anything. Projects that reject contributions almost always do so because the contributor did not follow the guidelines. Respect the process.
3
Start by submitting data
The easiest way to contribute is to run content and report your results. For drop rate projects, run a domain 10 times and report every drop. For tier list projects, run your character through Abyss and report clear times. Data submission requires patience, not technical skill. Every piece of raw data is valuable.
4
Work up to analysis
Once you have submitted enough data to understand the process, try interpreting the aggregated results. Look for patterns in the data — does a particular protocore stat distribution appear more frequently? Do certain builds consistently clear faster? Share your observations in the discussion channels for feedback.
5
Propose improvements or new projects
After you have established yourself as a reliable contributor, you can propose changes to existing projects or suggest new ones. Start with a clear proposal document — what problem does your project solve, what data do you need, who will help. Post it in the relevant channel and ask for feedback before building.

Contributing Without Technical Skills

The theorycrafting community depends heavily on contributors who are not programmers. These roles are essential and respected. If you can play the game and report what happens, you can contribute meaningfully.

DATA COLLECTION
Data Collector
Run specific content and report your results with precision. Drop rate projects need hundreds of data points to produce statistically significant results. Each domain run you report moves the community closer to accurate drop rate estimates. You need patience and attention to detail. Nothing else.
TESTING
Tester
Compare two builds in-game and report which performs better. For example, run Abyss floor 8 with Build A, then run it again with Build B. Record clear times, comfort level, and consistency. Testers bridge the gap between theoretical calculations and real gameplay performance.
PROOFREADING
Proofreader
Review community guides, tier list justifications, and analysis posts for accuracy and clarity. A second pair of eyes catches mistakes that the original author missed. Proofreading ensures that the community's shared knowledge base remains reliable and trustworthy.
COMMUNITY SUPPORT
Community Supporter
Answer questions in Discord and Reddit using established guides. Many players ask the same questions repeatedly — having knowledgeable community members who can direct them to existing resources reduces the burden on core theorycrafters and helps new players improve faster.

How Collaborative Tier Lists Work

The community maintains tier lists through a structured, transparent process. Understanding this process helps you contribute effectively and interpret the results correctly. A tier list is never the opinion of one person — it reflects the aggregated experience of dozens of contributors.

[1]
DATA COLLECTION
Crowd-sourced performance reports from contributors running Abyss, domains, and co-op content. Each report includes clear time, build details, and team composition.
[2]
WEIGHTING
Different content types are weighted differently. Abyss clear speed gets higher weight than domain clear speed. Co-op performance has its own separate weighting. Single-target and AoE scenarios are evaluated separately.
[3]
VOTING
Community members vote on proposed placements. Each vote includes a justification referencing data or personal testing experience. Votes without justifications are discarded to maintain quality.
[4]
REVISION CYCLE
The tier list is updated each patch with new character releases, balance changes, and accumulated data. Outdated placements are flagged and re-evaluated. The revision cycle ensures the tier list stays current.

How to participate in tier list voting: Most tier list projects open voting windows after each patch. During the voting window, you submit your experience with each character in the current patch. Be specific — "Xavier feels strong this patch" is not helpful, but "Xavier cleared Abyss floor 12 with 30 seconds remaining using a 4pc Light Seeker build at 7,800 DPS" is a useful data point that the voting committee can evaluate.

Starting Your Own Project

The community always needs new projects. If you see a gap — something the community needs that does not exist yet — you have the power to create it. The path from idea to active project follows a predictable pattern.

Identify a gapWhat does the community need that does not exist yet? Maybe a specific drop rate tracker for a new domain, a build comparison tool for a recently released character, or a resource calculator for an upcoming event. Look at what questions get asked repeatedly in Discord and Reddit — these are gaps waiting to be filled.
Gather initial dataStart with what you have. Run the content yourself 10-20 times and record the results. Build a small dataset that demonstrates the value of the project. A project with zero data is a theory. A project with 20 data points is a proof of concept that others can build on.
Build a prototypeYour prototype does not need to be polished. A simple Google Sheet with a few columns, a text document with your analysis, or a basic HTML page is enough. The prototype shows potential contributors exactly what you are trying to build and makes it easy for them to see how they can help.
Recruit contributorsPost your prototype in Discord and Reddit with a clear explanation of what you are building and what kind of help you need. Be specific — "I need people to run Domain X and report their drops" is better than "Join my project." People contribute when the ask is clear and the effort required is minimal.
Iterate based on feedbackEarly contributors will tell you what is working and what is not. Listen to them. Adjust your data format, your analysis methodology, and your project scope based on real feedback. The best community projects are shaped by the community, not dictated by the founder.

Starting small is the key. Do not try to build the ultimate all-in-one resource on your first attempt. Start with a narrow scope — one character, one domain, one content type. Prove that your approach works on a small scale. Once you have a working system and a group of reliable contributors, you can expand the scope. Every major community project started as a small experiment.

Community Etiquette & Best Practices

The theorycrafting community functions because contributors follow shared norms. These norms protect the integrity of the data, respect the work of original discoverers, and keep the community welcoming to new members.

Credit original discoverers
If you use a calculation method, a datamine finding, or an analysis technique that someone else developed, credit them explicitly. Reposting datamine findings without attribution damages trust and discourages the original discoverer from sharing future findings. A simple credit line takes seconds and preserves community goodwill.
Share raw data, not just conclusions
When you share a finding, include the raw data that supports it. Raw data enables others to verify your conclusions, apply different分析方法, and build on your work. A conclusion without supporting data is an opinion, not a contribution. The community values verifiable results over persuasive arguments.
Respect different playstyles
Whale, F2P, and mid-spender perspectives are all valid and valuable. A tier list made exclusively from whale data is not useful for F2P players. A strategy designed for F2P limitations may not be optimal for spenders. Good community resources account for multiple investment levels. When sharing advice, specify the investment level you are assuming.
Update your contributions when the game patches
Game patches can invalidate old data, change drop rates, rebalance characters, and introduce new mechanics. If you maintain a guide, a spreadsheet, or a data set, check it after every patch and update anything that has changed. Outdated information is worse than no information because it misleads players who trust the community's resources.

When in doubt, ask. If you are unsure whether a contribution is appropriate, whether a finding is already known, or whether your data format is correct, ask the community before submitting. A quick question in Discord costs you 30 seconds. A rejected contribution costs you the time you spent preparing it and may discourage you from trying again.

Summary: The Love and Deepspace theorycrafting community operates across Discord, Reddit, Google Sheets, and GitHub. Any player can contribute through data collection, testing, proofreading, or community support. Collaborative tier lists follow a structured process of data collection, weighting, voting, and revision. Starting a new project requires identifying a gap, gathering initial data, building a prototype, recruiting contributors, and iterating on feedback. Community norms require crediting discoverers, sharing raw data, respecting different playstyles, and keeping resources updated after patches. The community thrives because players contribute voluntarily — your participation, at any level, makes the ecosystem stronger for everyone.
